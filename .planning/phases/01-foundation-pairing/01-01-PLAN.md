  <behavior>
    - Test: constructor accepts a token string
    - Test: getVehicles() calls GET /vehicles?only_active=true with correct Authorization header
    - Test: getVehicles() returns parsed results array from response
    - Test: getVehicles() throws on 401 response (invalid token)
    - Test: getVehicles() throws on non-JSON response
    - Test: getVehicle(vin) calls GET /{vin}/state with authorization
    - Test: getVehicle(vin) returns parsed vehicle state
    - Test: getStatus(vin) calls GET /{vin}/status with authorization
    - Test: request method includes Authorization Bearer header
    - Test: request method rejects on HTTP 4xx/5xx with descriptive error
  </behavior>
  <action>
    Create `lib/tessie-client.js` implementing the TessieClient class using Node.js built-in `node:https` module. Follow the pattern from 01-RESEARCH.md exactly:

    1. Constructor takes `token` parameter, stores it, sets `this.baseUrl = 'api.tessie.com'`

    2. `async request(path, method = 'GET')` method:
       - Uses `node:https` to make request to `api.tessie.com`
       - Sets headers: `Authorization: Bearer ${this.token}`, `Accept: application/json`
       - Collects response data chunks
       - On HTTP 401: reject with Error('Invalid or expired API token')
       - On HTTP 4xx/5xx: reject with Error(`Tessie API error: ${statusCode}`)
       - Parses JSON response, rejects with Error('Invalid response from Tessie API') on parse failure
       - Returns parsed JSON object

    3. `async getVehicles()` method:
       - Calls `this.request('/vehicles?only_active=true')`
       - Returns `response.results` array

    4. `async getVehicle(vin)` method:
       - Calls `this.request('/' + vin + '/state')`
       - Returns full response object

    5. `async getStatus(vin)` method:
       - Calls `this.request('/' + vin + '/status')`
       - Returns full response object

    Export the class: `module.exports = TessieClient;`

    Create `tests/tessie-client.test.js` using `node:test` and `node:assert`:
    - Use `node:test` mock functionality to mock the `node:https` module's `request` function
    - Create a helper that simulates HTTP responses (status code, body)
    - Test all behaviors listed above
    - Each test should be independent (setup/teardown per test)

    IMPORTANT: Mock at the `https.request` level, not by monkey-patching the TessieClient. This tests the actual integration between TessieClient and the HTTP layer.
  </action>
